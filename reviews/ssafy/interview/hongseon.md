# 면접 (ssafy/interview) — hongseon

## 접근

**팀에서 유일하게 탐색도 시뮬레이션도 없이 닫힌 식으로 간 풀이다.**
`K` 칸마다 한 칸씩 비우면 2배 없이 담을 수 있는 정답 수가 `(k-1)·(n/k) + (n%k)` 라는 것을 세고,
그걸 넘는 만큼만 2배가 강제된다고 본다.

```cpp
int count = max(m - (n % k) - (k - 1) * (n / k), 0);   // 강제되는 2배 횟수
int left  = m - count * k;                             // 2배에 안 물린 나머지 정답
for (int i = 1; i <= count; i++) dp[i] = (dp[i - 1] + k) * 2;
cout << dp[count] + left;
```

`dp[i] = (dp[i-1] + k) * 2` 한 줄에 "K개를 연달아 맞히면 +K 하고 2배" 라는 규칙이 그대로 들어있고,
2배가 **누적 점수가 가장 작을 때 먼저 터지도록** 앞쪽에서 소비한다는 최소화 전략이 식의 순서에 박혀 있다.
이성일·안찬웅의 `O(N)` 배치 + 시뮬레이션보다 한 단계 더 접은 것이다.

**식 자체는 맞다.** `N ≤ 13` 의 모든 `(N, M, K)` 조합 **910건**을 O/X 전 배치 완전탐색과 대조해
**불일치 0건**이었다. 하드코딩된 `n=5, m=2, k=3` 도 완전탐색과 같은 `2` 가 나온다.

## 개선점

### 1. (치명) 입력을 읽지 않는다 — 어떤 입력에도 항상 `2` 를 출력한다 — <logic-edge-case>

```cpp
int n = 5;
int m = 2;
int k = 3;
```

`n, m, k` 가 상수로 박혀 있고 `cin` 이 한 번도 나오지 않는다. 테스트케이스 수 `T` 를 읽는 부분도,
`#tc` 를 붙여 출력하는 부분도 없다. **식이 맞는데도 제출하면 전부 오답이다** — 지금 이 프로그램은
표준입력이 무엇이든 `2` 한 줄만 찍는다. 팀의 다른 `면접` 풀이(`이성일/week6/면접.java`)와 같은 골격이 필요하다.

```cpp
int T; cin >> T;
for (int tc = 1; tc <= T; tc++) {
    int n, m, k; cin >> n >> m >> k;
    // ... 아래 식 그대로
    cout << "#" << tc << " " << dp[count] + left << "\n";
}
```

### 2. (치명) `int dp[10]` 인데 `count` 는 10을 넘을 수 있다 — <logic-edge-case>

`count` 는 "정답 수가 무2배 최대 수용량을 넘은 만큼" 이라 입력에 따라 얼마든지 커진다.
예를 들어 `n=40, m=30, k=2` 면 수용량이 `1·20 + 0 = 20` 이라 `count = 10` 이고,
`dp[10]` 에 쓰는 순간 **배열 밖 접근(UB)** 이다. `n=100, m=90, k=2` 면 `count = 40` 이다.

배열을 `m + 1` 크기로 잡거나(`count ≤ m`), 애초에 배열이 필요 없다 — 값 하나만 굴리면 된다.

```cpp
long long score = 0;
for (int i = 1; i <= count; i++) score = (score + k) * 2;
cout << score + left;
```

### 3. (중요) 점수가 지수로 커져서 `int` 를 넘는다 — <overflow>

`dp[i] = (dp[i-1] + k) * 2` 는 매 단계 2배라 `dp[count] ≈ k · 2^(count+1)` 로 지수 증가한다.
`count` 가 30 근처만 되어도 `int` 를 넘긴다 — 2번 예시인 `n=100, m=90, k=2` 는 `count = 40` 이라
`int` 로는 이미 깨지고(`long long` 으로는 아직 담긴다), 입력이 조금만 더 커지면 `long long` 도 못 담는다.

이건 코드가 아니라 **문제 제약 확인이 먼저 필요한 항목**이다. `N`·`K` 범위와 출력 형식(모듈러 여부)을
보고 자료형을 정해야 한다. 이성일 리뷰에도 같은 항목이 열려 있다 — 사내 문제라 지문을 못 봐서
셋 다 미해결 상태다. **문제지를 본 사람이 이 한 줄만 확인해 주면 된다.**

## 복잡도

- 시간: `O(count)` — 반복이 강제되는 2배 횟수만큼만 돈다. 탐색도 `O(N)` 순회도 없다
- 공간: `O(1)` — `dp` 를 값 하나로 접으면 상수

## 요약

**팀 세 사람의 면접 풀이 중 관찰이 가장 깊다.** "2배가 몇 번 강제되는가" 를 닫힌 식으로 세고,
그 2배를 점수가 작을 때 먼저 소비한다는 최소화 전략까지 식 한 줄에 넣었다 — 완전탐색 910건 대조에서
불일치 0건이다. 문제는 전부 그 식 바깥에 있다. 입력을 읽지 않아 항상 `2` 만 찍고, `dp` 배열이 10칸이라
조금만 큰 입력에서 배열 밖을 쓴다. 위 세 곳만 채우면 이 문제에서 제일 빠른 풀이가 된다.
