# 보호 필름 (swea/2112) — junsoo

## 접근

행마다 `안 씀 / A약 투입 / B약 투입` 세 갈래를 재귀로 펼치는 완전탐색이다. 세 가지 판단이 잘 들어가 있다.

**첫째, `row` 파라미터로 중복을 없앴다.** `visited` 배열로 "이 행을 썼는가"를 관리하면 같은 행 조합을 **순서만 바꿔서** 여러 번 탐색하게 된다(`{1,3}` 과 `{3,1}`). `row` 를 넘기며 앞으로만 진행하면 조합 하나가 정확히 한 번씩 나온다. 실패 버전(`junsoo.failed.md`)이 바로 이 차이로 16배 느렸고, 본인이 주석에 그 시행착오를 남겨두었다.

**둘째, `if(count >= result) return;` 가지치기.** 지금까지 쓴 약이 이미 최선 이상이면 더 볼 필요가 없다. 최적해에 빨리 도달할수록 잘 드는 가지치기다.

**셋째, 약을 넣은 직후 `isOK()` 로 먼저 확인하고, 통과하면 더 깊이 안 들어간다.**

```java
useMed(row, 0);
if(isOK()) { if(count + 1 < result) result = count + 1; }
else       { dfs(row + 1, count + 1); }
```

약을 더 넣어봐야 개수만 늘어나므로 조기 확정이 맞다. `result` 를 `K` 로 초기화한 것도 좋다 — 최악의 경우 K개면 항상 통과하므로 유효한 상한이고, 덕분에 가지치기가 처음부터 작동한다.

시작 전에 `isOK()` 를 한 번 검사해 0을 바로 반환하는 처리도 빠짐없다.

**검증**: 같은 저자의 실패 버전과 무작위 입력 60건(D=3~7, W=2~4, K=2~4)을 대조해 **출력이 전부 일치**함을 확인했다(둘은 속도만 다르다).

## 개선점

### 1. (사소) 파일명과 `public class Solution` — 이 파일만 규칙이 다르다 — `naming`

`compiles: false` 는 파일명 때문이다. 다만 이 파일은 다른 week5 파일들과 달리 클래스명이 `SWEA2112` 가 아니라 `Solution` 이라, `Solution.java` 로 두면 SWEA 제출 형식과도 맞는다. 실패 버전은 `SWEA2112` 로 되어 있어 두 파일의 규칙이 서로 다르다 — 어느 쪽이든 하나로 통일해두면 나중에 헷갈리지 않는다.

### 2. (사소) `isOK()` 를 매 리프에서 전체 열을 다시 훑는다 — `redundant-loop`

`isOK()` 는 항상 `W`개 열 × `D`행을 전부 검사한다. 약을 넣은 행 하나만 바뀌었는데도 전체를 다시 본다. 지금 입력 크기(D ≤ 13, W ≤ 20)에서는 156ms로 충분히 빠르니 **고칠 필요는 없다.** 다만 더 큰 입력이었다면 "열별로 이미 K연속을 만족하는지"를 들고 다니며 갱신하는 쪽이 정석이다.

굳이 하나만 손보자면, `isOK()` 가 한 열이라도 실패하면 즉시 `return false` 하는 건 이미 되어 있으니 그대로 두면 된다.

## 복잡도

- 시간: `O(3^D × D × W)` — 행마다 3갈래, 리프마다 `isOK()` 가 `D × W`. 가지치기 두 개(`count >= result`, 조기 확정)가 실제로는 이 상한보다 훨씬 적게 돌게 만든다. D=13, W=20, K=7 최악 입력에서 **156ms** 로 측정됐다.
- 공간: `O(D × W)` — `board` + 재귀 깊이 `D`.

## 요약

`visited` 대신 `row` 파라미터로 순열 중복을 제거한 것이 이 풀이의 핵심이고, 본인이 실패 버전과의 차이를 주석에 정확히 기록해두었다. 가지치기 두 개도 제자리에 들어가 있어 실측 156ms로 여유가 크다. 지적할 만한 로직 결함은 없다.
