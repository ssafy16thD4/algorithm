# 핀볼 게임 (swea/5650) — chanung

## 접근

빈 칸마다 **4방향 전부** 공을 쏴 보고, 한 번 쏘면 끝날 때까지 while 로 굴린다. 블록 반사는
`reflect(block, dir)` 한 함수에 모아서 시뮬레이션 루프가 짧게 유지된다. 웜홀은 입력을 읽을 때
번호별 좌표 2개를 `hole[번호][0/1]` 에 담아두고, 들어온 좌표가 0번이면 1번으로 보낸다.

## 개선점

### 1. (수정 완료 / 치명) 발사 방향을 우측 하나만 시도했다 — `wrong-algorithm`

`dfs(i, j, 0, 0)` — 빈 칸마다 `dir=0`(우) 로 한 번만 쐈다. 이 문제는 공을 놓을 칸뿐 아니라 **발사
방향도 자유**라, 같은 칸에서도 방향에 따라 점수가 전혀 다르다. `for(dir=0..3)` 로 바꿨다.

### 2. (수정 완료 / 치명) 빈 칸을 전부 "출발 지점"으로 오인해 즉시 종료했다 — `logic-edge-case`

```java
else if(graph[nx][ny] == graph[startX][startY]) {   // 둘 다 0 -> 모든 빈 칸이 여기 걸린다
    maxScore = Math.max(maxScore, score);
    return;
}
```

출발 칸도 값이 0, 지나가는 빈 칸도 값이 0 이다. **값**을 비교했기 때문에 공은 빈 칸을 한 칸도
지나가지 못하고 첫 이동에서 끝났다. 좌표 비교(`nx == sx && ny == sy`)로 바꿨다.

### 3. (수정 완료 / 치명) 벽에 부딪히면 방향만 바꾸고 아무 일도 하지 않았다 — `logic-edge-case`

```java
if(nx < 0 || nx >= n || ny < 0 || ny >= n) {
    dir = (dir + 2) % 4;   // 방향만 뒤집고 -> 이 뒤에 재귀 호출도 점수 증가도 없다
}
```

벽 반사도 점수 +1 인데 점수가 오르지 않았고, 이어서 굴러가지도 않아 그 지점에서 탐색이 끊겼다.

### 4. (수정 완료 / 치명) 웜홀이 구현돼 있지 않았다 — `wrong-algorithm`

주석에는 "동일한 숫자를 가진 다른 웜홀로 나옴" 이라고 적혀 있었지만 코드는 `return` 이었다.
웜홀에 들어가는 순간 게임이 끝나서, 웜홀을 통과해야 나오는 높은 점수 경로가 전부 누락됐다.
지금은 짝 좌표로 순간이동하고 **방향은 유지, 점수는 오르지 않는다.**

### 5. (수정 완료 / 치명) 4번 블록 분기에 도달 불가능한 `dir == 4` — `off-by-one`

`if(dir == 3 || dir == 4)` 였다. `dir` 은 0~3 이라 `dir == 4` 는 절대 참이 안 되고, `dir == 2`(좌)로
4번 블록에 들어오면 어느 분기에도 안 걸려 **방향이 안 바뀐 채 직진**했다. `dir == 2 || dir == 3` 이 맞다.

블록 표를 기하로 다시 확인했다. 반사 방향은 세 방향 배열 `dx={0,1,0,-1}, dy={1,0,-1,0}`(0=우,1=하,2=좌,3=상) 기준이다.

| 블록 | 막힌 두 면 | 빗면 | 꺾임 |
| ---- | ---------- | ---- | ---- |
| 1 | 좌·하 | `\\` | 좌→상, 하→우 |
| 2 | 좌·상 | `/` | 좌→하, 상→우 |
| 3 | 상·우 | `\\` | 우→하, 상→좌 |
| 4 | 우·하 | `/` | 우→상, 하→좌 |
| 5 | 사각형 | — | 항상 반대 |

원래 코드의 1~3번 표는 이 기하와 정확히 일치했다. 4번만 오타였다.

### 6. (수정 완료 / 치명) DFS 첫 줄의 디버그 출력 — `dead-code`

`System.out.println("x: " + x + ...)` 가 호출마다 찍혀서, 알고리즘이 전부 맞아도 표준출력이
오염돼 100% 오답이 난다. **채점 서버는 표준출력만 본다** — 제출 전 반드시 지운다.

### 7. (수정 완료 / 중요) 재귀를 while 루프로, `package` 제거, `public class Solution`

`package practive;` + `class Main` 이라 SWEA 에 그대로 제출할 수 없었다. 그리고 공은 경로가
길어질 수 있어 재귀보다 while 이 안전하다(스택 오버플로 회피).

## 검증

```
5×5, 가운데(2,2)에만 5번 블록      -> #1 2   (블록에 맞고 되돌아와 벽 한 번, 손계산 일치)
5×5, 네 모서리에 1/2/4/3 블록       -> #1 8   (테두리를 한 바퀴 돌며 블록 4번 + 벽 4번, 손계산 일치)
```

두 번째 케이스를 손으로 따라가면 (0,1)에서 좌로 발사 → 블록1(+1) → 벽(+1) → 블록4(+1) → 벽(+1)
→ 블록3(+1) → 벽(+1) → 블록2(+1) → 벽(+1) → 출발칸 복귀로 정확히 8이다.
**SWEA 채점 데이터로 돌린 것은 아니다.**

## 복잡도

- 공간: `O(N^2)`

## 요약

블록 반사표(1~3번)를 기하학적으로 정확히 세운 것이 이 풀이의 실력이다. 무너진 건 그 주변이었다 —
출발 판정을 값으로 한 것, 벽 반사에서 굴리기를 잊은 것, 웜홀을 주석에만 남긴 것, 방향을 하나만 쏜 것.
**주석에 규칙을 다 적어 놓고 코드에 옮기지 않은 자리**가 그대로 오답 지점이 됐다는 게 이 문제의 교훈이다.
