# 핀볼 게임 (swea/5650) — seongil

## 접근

`dirMapper`(블록번호 → 방향 → 새 방향)와 `pairWHoles`(웜홀번호 → 좌표 두 개)를 `Map` 으로 들고, 한 루프 안에서 벽·블랙홀·시작점복귀·블록·웜홀을 차례로 처리한다. 방향 반전을 `dir = 4 - dir - 1` 한 줄로 통일한 것과, 삼각형 블록에서 **평행변에 부딪히는 경우를 `dirMapper` 의 `null` 로 표현**해 반전으로 떨어뜨린 처리는 깔끔한 정리다.

`visited[dir][x][y]` 로 **(방향, 위치) 상태**를 기록해 순환을 감지하는 것도 옳은 방향이다. 같은 문제를 푼 김준수 코드는 순환 감지가 없어 안전 상한값을 그대로 점수로 반환하는 버그가 있다(`reviews/swea/5650/junsoo.md`).

## 개선점

### 1. (중요) 시작점에서 곧바로 벽을 향하는 경우를 놓친다 — `logic-edge-case`

**실제로 돌려본 입력** — 3×3 빈 판:

```
1
3
0 0 0
0 0 0
0 0 0
```

- 이 코드 출력: `#1 1`
- 김준수 코드(위 `ㅊ` 제거 후) 출력: `#1 2`

**손으로 따라가 보면 2가 맞다.** `(0,0)` 에서 **위쪽**으로 출발하면 바로 위가 벽이므로 튕기고(+1) 방향이 아래로 바뀐다. 열 0을 따라 `(1,0) → (2,0)` 으로 내려가면 아래도 벽이라 다시 튕기고(+1) 방향이 위로 바뀐다. 그대로 올라가 `(0,0)` 시작점에 도달해 종료 — 벽 두 번, 점수 **2** 다.

이 코드가 1을 내는 것은 루프 진입 시점의 좌표·검사 순서 때문으로 보인다. 벽 처리(`if (!inRange(x,y))`)가 루프 **머리**에 있어서, 출발 직후 첫 이동으로 판을 벗어나는 궤적의 처리 순서가 나머지와 달라진다. 시작 좌표를 어떻게 잡고 첫 스텝을 어디서 밟는지 다시 확인해볼 자리다.

**검증 범위 명시**: 두 구현이 서로 다른 값을 낸다는 것과, 3×3 빈 판의 정답이 손계산으로 2라는 것까지는 확인했다. 채점 서버에 넣어본 것은 아니다.

### 2. (중요) 순환을 감지했을 때 `return 0` 은 점수를 버린다 — `logic-edge-case`

```java
if (visited[dir][x][y]) return 0;
```

같은 (방향, 위치)를 다시 만나면 **그때까지 쌓은 `cnt` 를 통째로 버리고 0을 반환**한다. 순환에 들어갔다는 것은 "더 이상 점수가 늘지 않는다"는 뜻이지 "지금까지의 점수가 무효"라는 뜻이 아니다. 이미 벽·블록에 부딪혀 얻은 점수는 유효하므로 `return cnt;` 가 맞다.

핀볼 문제는 공이 항상 시작점으로 돌아온다고 알려져 있어 이 분기가 안 타는 게 정상이지만, 만약 타고 있다면 **최댓값을 조용히 깎아먹는다.** 개선점 1의 증상과 같은 뿌리일 수 있으니 함께 살펴보는 게 좋다.

### 3. (사소) `Map<Integer, Map<Integer, Integer>>` 대신 배열이면 충분하다 — `collection-choice`

블록 번호는 1~5, 방향은 0~3으로 **둘 다 작고 연속된 정수**다. `dirMapper.get(board[x][y]).get(dir)` 는 해시 조회 두 번 + 언박싱인데, `int[6][4]` 한 장이면 `table[block][dir]` 로 끝난다. 평행변 충돌을 `null` 로 표현하던 자리는 `-1` 로 두면 된다:

```java
static final int[][] REFLECT = new int[6][4];   // -1 = 평행변, 반전 처리
...
int nd = REFLECT[board[x][y]][dir];
dir = (nd == -1) ? 3 - dir : nd;
```

`pairWHoles` 도 같은 이유로 `int[11][2][2]` 가 낫다. 가장 안쪽 루프에서 도는 조회라 상수배 차이가 그대로 드러난다.

## 복잡도

- 시간: `O(N^4)` — 시작점 `N^2` × 방향 4 × 궤적 `O(N^2)`. `Map` 조회 상수가 붙는다.
- 공간: `O(N^2)` — `board` + `visited[4][N][N]`.

## 요약

순환 감지를 `(방향, 위치)` 상태로 잡은 것과 평행변 충돌을 별도 케이스로 분리한 것은 이 문제의 까다로운 부분을 제대로 본 것이다. 다만 3×3 빈 판에서 손계산 정답 2 대신 1이 나와, **출발 직후 벽에 부딪히는 궤적**의 처리가 어긋나 있다. 순환 시 `return 0` 도 점수를 버리는 쪽이라 같이 고쳐야 한다.
