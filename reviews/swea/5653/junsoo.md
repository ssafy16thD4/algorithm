# 줄기세포배양 (swea/5653) — junsoo

## 접근

세포를 비활성(`unactives`) → 활성(`actives`, 우선순위 큐) → 사망 예정(`sleeps`) 세 큐로 옮겨 다니는
상태 머신으로 시뮬레이션한다. 매 턴 세 큐를 정해진 순서(사망예정 → 활성 → 비활성)로 처리하고, 각 큐마다
`len = queue.size()`를 턴 시작 시점에 스냅샷 떠서 그 턴에 새로 들어온 항목이 같은 턴에 중복 처리되지
않게 막은 패턴이 세 곳 모두 일관되게 적용돼 있다. 자식 세포에 `currHp = -1` 마커를 달아 "이번 턴에
갓 태어나 나이를 먹지 않아야 함"을 표시하는 것도 상태 전이 타이밍을 정확히 맞추려는 의도가 코드에
그대로 드러난다. 격자 크기(351×351)를 도입부 주석에서 `hp=1`인 세포가 가장 빨리 퍼진다는 전제로
150칸 여유를 미리 계산해둔 것도 눈에 띈다 — 아래에서 직접 손으로 다시 따라가봤고 계산이 맞았다.

## 개선점

### 1. (치명) 컴파일이 안 된다 — `import` 문법 오류 — `missing-return`

```
김준수/week1/SWEA5653.java:23: error: <identifier> expected
import java.io.;
               ^
김준수/week1/SWEA5653.java:24: error: <identifier> expected
import java.util.;
                 ^
```

`java.io.*`, `java.util.*` 에서 `*` 가 빠지고 `.` 로 끝났다. 이것 때문에 `BufferedReader`,
`StringTokenizer`, `Queue`, `ArrayDeque`, `PriorityQueue` 를 아무것도 못 찾아서 전체가 컴파일되지
않는다. 태그 목록에 "컴파일 실패"에 정확히 맞는 태그가 없어 `missing-return`(반환 누락/컴파일 실패
그룹)을 붙였다. `import java.io.*;` / `import java.util.*;` 로 별표만 넣으면 해결된다 — 다른 코드
수정은 필요 없어 보인다(직접 고치진 않았다).

### 2. (중요) 격자 경계를 벗어나는지 코드로 확인하지 않는다 — `logic-edge-case`

```java
int nx = c.x + dx[i];
int ny = c.y + dy[i];

if(!visited[nx][ny]) {   // nx, ny 가 0~350 범위 안인지 검사 없이 바로 인덱싱
```

주석의 "150(여유) - 50(초기영역) - 150(여유) = 350" 계산을 손으로 다시 따라가봤다.
`hp=1`인 세포가 가장 빠르게 퍼지는 경우를 상태 전이 순서대로 추적하면(비활성 1턴 → 활성 1턴에
번식하며 즉시 사망 → 자식이 다음 턴부터 같은 주기 반복), 한 세대가 퍼지는 데 2턴이 걸리고
`K<=300`이면 최대 150세대, 즉 초기 위치에서 최대 150칸까지만 퍼진다 — 주석의 계산과 일치했다.
그래서 **현재 입력 제약(`N,M<=50`, `K<=300`)에서는 배열을 벗어나지 않는다고 판단된다.**

다만 이 안전성은 "이 계산이 맞다"는 걸 코드가 스스로 보장하지 않고 전적으로 사전 계산에 의존한다.
계산이 문제 제약과 조금이라도 어긋나거나(예: `hp=1` 세포의 상태 전이가 내가 추적한 것과 실제
채점기 규칙이 다르면) `ArrayIndexOutOfBoundsException` 으로 곧장 죽는다. 배열 크기를 조금 더
여유 있게 잡거나(`+1`~`+2` 정도) 최소한 방어적으로 범위 검사를 한 줄 추가해두면, 계산이 딱 들어맞지
않는 경우에도 조용히 실패하지 않는다.

```java
if(nx < 0 || nx > 350 || ny < 0 || ny > 350) continue;
if(!visited[nx][ny]) { ... }
```

## 복잡도

- 시간: `O(K · 격자크기)` — 매 턴 세 큐를 순회하며 활성 세포마다 4방향을 검사. 격자 크기가 351×351로
  고정돼 있어 큐 크기가 이를 넘지 않는다.
- 공간: `O(격자크기)` — `visited` 배열이 지배적.

## 요약

`import` 오타만 고치면 상태 머신 자체는 세 큐의 처리 순서와 스냅샷 패턴이 꼼꼼해서 로직 버그는
찾지 못했다. 격자 크기 351을 뒷받침하는 "150칸 여유" 계산도 직접 손으로 다시 확인했을 때 맞았다.
다만 그 계산에 전적으로 기대어 배열 경계 검사를 생략한 부분은, 계산이 어긋날 경우의 방어가 전혀
없다는 점에서 다듬을 여지가 있다.
