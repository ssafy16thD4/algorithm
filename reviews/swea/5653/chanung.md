# 줄기세포배양 (swea/5653) — chanung

## 접근

세포를 **활성화 시각 순 우선순위 큐**로 관리하고, `time` 을 1부터 K까지 진행하며 그 시각에 활성화되는 세포만 꺼내 번식시킨다. 이 문제의 까다로운 규칙 두 개를 정확히 처리했다.

**첫째, 동시 번식의 우선순위.** 같은 시각에 여러 세포가 같은 빈 칸을 노릴 때 **생명력이 큰 세포가 이긴다.** `compareTo` 가 그걸 그대로 표현한다:

```java
if (this.time != o.time) return Integer.compare(this.time, o.time);  // 활성화 시각 오름차순
return Integer.compare(o.life, this.life);                            // 생명력 내림차순
```

시각이 같으면 생명력 큰 쪽이 먼저 나오므로, 먼저 꺼낸 세포가 칸을 차지하고 뒤에 오는 세포는 `graph[nx][ny] != 0` 에 걸려 물러난다. 이 정렬 하나로 충돌 규칙이 해결된다.

**둘째, 시각 계산.** 자식의 활성화 시각을 `time + 1 + cur.life` 로 잡았다. 태어난 시각이 `time+1` 이고 거기서 생명력만큼 비활성 상태로 기다린다는 규칙이 식에 그대로 있다. 사망 판정 `cur.time + cur.life <= k` 도 "활성화 시각 + 생명력 = 사망 시각" 이라는 주석대로다.

격자를 `max(n,m) + 2K + 2` 로 잡아 **음수 좌표를 offset `k` 로 흡수**한 것도 깔끔하다. 세포는 K시간 동안 사방으로 최대 K칸 퍼지므로 이 크기면 경계를 벗어나지 않는다.

`total - dead` 로 답을 내는 것도 좋다 — 살아 있는 세포를 매번 세는 대신 **태어난 수와 죽은 수만 누적**해서 마지막에 뺀다.

**검증**: 이성일 통과 코드와 무작위 입력 60건(N,M=2~5, K=1~8)을 대조했고 **두 구현이 전부 일치**했다.

## 개선점

### 1. (사소) 파일명이 `public class Solution` 과 달라 그대로는 컴파일되지 않는다 — `naming`

`compiles: false` 는 파일명 때문이다. `줄기세포배양.java` 안에 `public class Solution` 이 있어서 나는 오류이고, 파일명을 `Solution.java` 로 두면 그대로 컴파일된다(확인함). 알고리즘 쪽에는 오류가 없다.

### 2. (사소) `time + 1 > k` 검사를 루프 조건으로 올릴 수 있다 — `magic-branch`

```java
if (time + 1 > k) continue;   // 자식은 time+1에 태어나니까 K 넘으면 생성 자체를 안 함
```

`time` 이 `k` 일 때만 참이므로, 사실상 마지막 한 바퀴에서만 걸린다. 의미는 맞지만 "왜 여기서 `continue` 인가"를 읽는 사람이 한 번 생각해야 한다. 사망 집계는 계속해야 하므로 루프를 줄일 수는 없고, 지금 형태에 주석이 붙어 있는 게 차선으로는 낫다 — 굳이 고칠 필요는 없다.

### 3. (사소) `size` 계산이 필요한 것보다 조금 넉넉하다 — `space-complexity`

`max(n,m) + 2k + 2` 는 행·열 중 큰 쪽 기준으로 정사각 격자를 잡는다. 실제로 필요한 건 행 `n + 2k`, 열 `m + 2k` 라 직사각형이면 낭비가 생긴다. N, M ≤ 50, K ≤ 300 정도라 최대 650×650 = 40만 칸이고 메모리는 넉넉하니 **실질 문제는 없다.** 정사각으로 두면 인덱스 실수가 줄어드는 이점도 있어서 트레이드오프로 보면 된다.

## 복잡도

- 시간: `O(셀수 × log 셀수)` — 세포 하나가 큐에 한 번 들어가고 나오며, 넣고 뺄 때 `log` 가 붙는다.
- 공간: `O((N + 2K)^2)` — 격자 + 큐.

## 요약

**시각 오름차순 + 생명력 내림차순**이라는 정렬 하나로 동시 번식 충돌 규칙을 해결한 것이 이 풀이의 핵심이고, 시각 계산(`time + 1 + life`)과 사망 판정도 규칙과 정확히 맞다. `total - dead` 로 집계를 미룬 것도 좋은 판단이다. 컴파일 실패는 파일명뿐이고 로직에 지적할 것은 없다.
