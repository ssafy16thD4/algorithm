# 줄기세포배양 (swea/5653) — seongil

## 접근

시간을 1씩 진행하면서 **살아 있는 세포만 덱으로 넘기는** 방식이다. 세포마다 `currVal` 을 깎아가다 0이 되는 순간 활성화로 보고 번식시킨다. 격자를 아예 만들지 않고 `Map<Node, Node>` 로 좌표 → 세포를 관리해서, **음수 좌표나 격자 크기 계산이 필요 없다.** `Node` 에 `equals`/`hashCode` 를 좌표 기준으로 오버라이드해 맵의 키로 쓴 것이 그 선택을 받쳐준다.

한 시각의 번식을 `births` 라는 **별도 맵에 모았다가 나중에 반영**하는 것이 핵심 판단이다. 같은 시각에 여러 세포가 같은 빈 칸을 노릴 때, 바로 격자에 쓰면 먼저 처리된 쪽이 이겨버린다. 임시 맵에 모아두고 경합이 나면 큰 값으로 교체하는 방식이라 **처리 순서와 무관하게** 규칙대로 결정된다. 안찬웅 풀이가 우선순위 큐 정렬로 푼 것과 같은 문제를 다른 방법으로 해결했다.

주석에 "아이디어 47분, 구현 15분 하다가 멈춤 + 35분" 처럼 **어디서 막혔는지**를 남겨둔 것도 나중에 본인이 다시 볼 때 값어치가 있다.

**검증**: 안찬웅 통과 코드와 무작위 입력 60건(N,M=2~5, K=1~8)을 대조했고 **두 구현이 전부 일치**했다.

## 개선점

### 1. (중요) `Map<Node, Node>` 는 해시 비용이 크다 — `collection-choice`, `boxing-cost`

세포 하나를 확인할 때마다 `Objects.hash(x, y)` 로 해시를 계산하고(내부에서 `Integer` 박싱이 일어난다), 버킷을 찾고, `equals` 로 비교한다. 이 조회가 번식 시도마다 네 방향으로 돌기 때문에 가장 안쪽 루프에 들어간다.

좌표 범위가 정해져 있으므로(`K` 시간 동안 사방 최대 `K` 칸) **offset을 준 2차원 배열**이면 조회가 `O(1)` 상수에 박싱도 없다. 안찬웅 풀이가 `k + i`, `k + j` 로 offset을 주는 방식이다:

```java
int size = Math.max(n, m) + 2 * k + 2;
int[][] grid = new int[size][size];   // 0 = 빈칸
// 좌표 (i, j) -> grid[k + i][k + j]
```

배열 크기가 최대 650×650 = 40만 칸이라 메모리도 문제없다. 맵을 쓸 이유가 있다면 좌표를 `long` 하나로 인코딩(`x * 100000L + y`)해 `HashMap<Long, Node>` 로 두는 것만으로도 `Objects.hash` 와 `equals` 호출이 사라진다.

### 2. (사소) 매 시각마다 `Deque` 와 `HashMap` 을 새로 만든다 — `redundant-collection`

```java
while (t < k) {
    Deque<Node> spares = new ArrayDeque<>();
    Map<Node, Node> births = new HashMap<>();
```

`K` 가 최대 300 정도라 컬렉션 객체가 600개 만들어지는 것 자체는 큰 비용이 아니다. 다만 `births` 는 `clear()` 로 재사용할 수 있고, 그러면 시각마다 해시 테이블을 새로 할당하지 않는다. 1번을 고치는 김에 같이 정리할 만한 자리다.

### 3. (사소) 답을 `deq.size()` 로 낸다 — 의미가 코드에 드러나지 않는다 — `naming`

`deq` 는 "다음 시각으로 넘길 살아 있는 세포"라 시뮬레이션이 끝난 시점에는 곧 정답이지만, 변수 이름이 `deq` 라 그 사실이 읽히지 않는다. `alive` 정도면 마지막 줄이 그대로 설명이 된다. 안찬웅 풀이는 `total - dead` 로 같은 값을 다르게 구한다.

## 복잡도

- 시간: `O(K × 살아있는 세포수)` 에 해시 조회 상수가 곱해진다. 배열로 바꾸면 그 상수가 사라진다.
- 공간: `O(전체 세포수)` — 맵 + 덱. 격자를 안 만드는 대신 세포 수에 비례한다.

## 요약

한 시각의 번식을 `births` 맵에 모았다가 반영해서 **경합을 처리 순서와 무관하게** 만든 것이 정확한 판단이고, 격자 없이 맵으로 좌표를 다뤄 음수 좌표 문제를 피한 것도 깔끔하다. 답도 맞다. 남은 것은 비용 쪽인데, `Map<Node, Node>` 의 해시·박싱을 **offset 2차원 배열**로 바꾸면 가장 안쪽 루프의 상수가 눈에 띄게 줄어든다.
