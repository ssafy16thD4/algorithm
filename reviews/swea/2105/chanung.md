# 디저트 카페 (swea/2105) — chanung

## 접근

`dfs(x, y, cnt, direction)` 가 **한 칸만 움직이고, `dir` 유지 또는 `dir+1` 로 꺾기 두 갈래만 재귀**한다. 이 정리가 이 풀이의 핵심이다. "한 방향으로 쭉 밀고 가다가 꺾는다"를 루프로 쓰지 않고 **매 칸의 이지선다**로 바꾸면, 사각형의 네 변을 따로 다룰 필요가 없어진다. 함수가 20줄이 안 된다.

```java
for(int dir=direction; dir<=direction+1 && dir<4; dir++)
```

이 한 줄에 "직진 or 꺾기"와 "네 번째 방향 이후로는 못 꺾는다"가 같이 들어 있다.

중복 검사도 좋다. 좌표 방문 배열 대신 **디저트 번호를 인덱스로 쓰는 `vis[101]`** 하나만 둔다. 같은 칸을 두 번 밟는 경우는 그 칸의 번호가 이미 `true` 라서 자동으로 걸리므로, 좌표 `visited` 배열이 아예 필요 없다. 검사가 `O(1)` 이고 백트래킹 복원도 한 줄이다.

시작점 복귀 처리(`if(nx == startX && ny == startY)`)를 `vis` 검사보다 **앞에** 둔 것도 맞다. 시작점의 디저트 번호는 이미 `true` 라서 순서가 바뀌면 사각형이 절대 완성되지 않는다.

**검증**: 김준수 통과 코드와 무작위 입력 60건(N=4~9, 디저트 번호 1~12)을 대조했고 **두 구현이 전부 일치**했다.

## 개선점

### 1. (사소) 시작점 범위 `i<n-2`, `j` 는 `1..n-2` — 근거가 코드에 안 드러난다 — `magic-number`

```java
for(int i=0; i<n-2; i++) {
    for(int j=1; j<n-1; j++) {
```

가장 작은 사각형이 대각선 한 칸씩이라 세로로 2칸, 가로로 양옆 1칸씩의 여유가 필요하다는 계산인데, 이 `-2` 와 `1` 이 어디서 나왔는지는 주석에도 없다. 답에는 영향이 없지만(범위를 좁힌 쪽이라 유효한 시작점을 빠뜨리지도 않는다) 나중에 본인이 다시 읽을 때 한 번 멈추게 되는 자리다. `// 최소 사각형이 2행, 좌우 1칸씩 필요` 정도면 충분하다.

### 2. (사소) `maxCnt = -1` 초기값이 출력 규약과 맞물려 있다 — `logic-edge-case`

사각형을 하나도 못 만들면 `-1` 이 그대로 출력되는데, 이건 이 문제가 요구하는 동작이라 **맞다**. 다만 `cnt` 를 1부터 시작하므로(`dfs(i, j, 1, 0)`) 실제 가능한 최솟값은 4이고 `-1` 과 섞일 일이 없다는 점이, 코드만 봐서는 바로 안 보인다. 지적이라기보다 확인해둘 지점이다.

## 복잡도

- 시간: `O(N^4)` — 시작점 `N^2` × 사각형 모양 `N^2`. 중복 검사가 `O(1)` 이라 여기에 경로 길이가 곱해지지 않는다.
- 공간: `O(N^2)` — `graph`. `vis` 는 101 고정이라 상수.

## 요약

"직진 or 꺾기 이지선다"로 사각형 탐색을 정리한 것과, 좌표 대신 **디저트 번호를 방문 배열의 인덱스로 쓴** 두 판단이 이 풀이를 짧고 빠르게 만들었다. 같은 문제를 while 루프로 푼 김준수 코드와 비교하면 함수 길이가 절반이고 중복 검사가 `O(N)` → `O(1)` 이다. 지적할 만한 결함은 없다.
