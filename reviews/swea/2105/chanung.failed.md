# 디저트 카페 (swea/2105) — chanung (실패 버전)

## 접근

시작점마다 BFS를 돌려 "중복 없는 디저트를 먹으며 갈 수 있는 칸"을 최대한 많이 방문하고, 방문한 칸 수(`cnt`)를 답 후보로 삼는다. 통과 버전(`chanung.md`)과 비교하면 **사각형이라는 제약을 아예 표현하지 못한 것**이 갈라지는 지점이다.

## 개선점

### 1. (치명) 사각형 경로를 세는 게 아니라 "연결된 영역 크기"를 센다 — `wrong-algorithm`

이 문제는 **대각선 네 변으로 닫힌 사각형**을 찾아야 한다. 필요한 것은 세 가지다.

1. 방향을 `dir → dir+1` 순서로만 꺾을 것
2. 정확히 네 번 꺾어 **시작점으로 되돌아올 것**
3. 그 경로 위의 디저트가 전부 다를 것

그런데 이 BFS는 3번만 검사하고 1·2번을 전혀 보지 않는다. `for(int dir=0; dir<4; dir++)` 로 **네 방향 아무 데나** 뻗어나가고, 시작점 복귀 검사도 없다. 그래서 `cnt` 는 경로 길이가 아니라 **시작점에서 도달 가능한 칸의 개수**가 된다 — 닫힌 사각형이 아니어도, 심지어 사각형을 만들 수 없는 배치에서도 큰 값이 나온다.

BFS로 `poll` 한 횟수를 세는 구조 자체가 "경로"와 맞지 않는다. 큐에 들어간 칸들은 서로 다른 갈래에 속하는데 그걸 전부 한 경로처럼 더하고 있다.

### 2. (치명) `visNum` 을 시작점마다만 초기화하고 BFS 안에서 되돌리지 않는다 — `uninitialized-state`

```java
visNum = new int[101];
visNum[graph[i][j]] = 1;
bfs(i, j);
```

`visNum` 은 시작점 하나당 한 번 새로 만들어지고, `bfs` 안에서는 `visNum[graph[nx][ny]] = 1` 로 **켜기만 한다.** 백트래킹 복원이 없다.

BFS는 여러 갈래를 동시에 펼치므로, 한 갈래에서 먹은 디저트가 **다른 갈래까지 막아버린다.** 통과 버전은 DFS로 바꾸면서 `vis[...] = true → 재귀 → vis[...] = false` 로 되돌리게 만들어 이 문제를 없앴다. 경로 단위 상태는 경로가 끝날 때 되돌려야 한다.

### 3. (중요) 시작점 범위가 통과 버전과 다르다 — `logic-edge-case`

```java
for(int i=1; i<n-1; i++)      // 실패 버전
for(int i=0; i<n-2; i++)      // 통과 버전
```

행 범위가 `1..n-2` 로 잡혀 있어 **0행에서 시작하는 사각형을 아예 못 찾는다.** 사각형의 위 꼭짓점은 0행에도 놓일 수 있으므로 유효한 후보를 빠뜨린다. (1·2번이 이미 치명적이라 이것만 고쳐도 답은 안 맞는다.)

### 4. (사소) `cnt` 를 `poll` 마다 증가시키는데 시작 칸이 두 번 세어진다 — `off-by-one`

`cnt=0` 으로 시작해 `poll` 할 때마다 `cnt++` 하므로 방문 칸 수와 같아지는데, 애초에 세는 대상 자체가 틀려서 이 계산이 의미를 갖지 못한다.

## 복잡도

- 시간: `O(N^4)` — 시작점 `N^2` × BFS `N^2`. 통과 버전과 같은 차수지만 **다른 것을 세고 있다.**
- 공간: `O(N^2)` — `vis` + 큐.

## 요약

"디저트가 겹치면 안 된다"는 조건 하나만 구현했고, 정작 이 문제를 정의하는 **꺾는 순서와 시작점 복귀**를 담지 못했다. 그래서 답이 사각형 길이가 아니라 도달 가능 영역 크기가 되어버렸다. 통과 버전은 BFS를 DFS로 바꿔 `dir → dir+1` 이지선다와 시작점 복귀 검사를 넣고, 상태를 경로 단위로 되돌리게 만들어 세 문제를 한 번에 해결했다.
