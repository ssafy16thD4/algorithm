# 벌꿀채취 (swea/2115) — hongseon

> 판정을 못 했다는 뜻이다. 아래는 전부 코드를 읽고 쓴 것이고, 반례를 돌려본 것은 없다.

## 접근

"각 시작칸의 최대 수익" 을 `max_board` 에 먼저 채우고, 그다음 두 일꾼의 배치를 훑는 2단 구조다.
수익 계산과 배치 탐색이 완전히 분리돼서 각각을 따로 검산할 수 있다.

`find_max` 가 **선택/미선택 두 갈래의 순수 재귀**인 것이 좋다.

```cpp
int not_choose = find_max(i, j, k + 1, total, max_value);
int choose = -1;
if (total + board[i][j + k] <= c)
    choose = find_max(i, j, k + 1, total + board[i][j + k], max_value + board[i][j+k] * board[i][j+k]);
return max(not_choose, choose);
```

`visited` 배열이나 되돌리기가 없이 인자로만 상태가 흐르기 때문에, 백트래킹에서 흔한
"되돌리기를 빠뜨려 다음 탐색이 오염되는" 실수가 구조적으로 불가능하다.
수익이 `(합)²` 이 아니라 `Σ(각 벌통)²` 이라 큰 값을 통째로 담는 탐욕이 안 통하는 문제인데,
부분집합 전탐색으로 정면 돌파한 판단이 정확하다.

**겹침 판정이 특히 정확하다.**

```cpp
for (int j = 0; j <= n - m; j++)          // M칸이 다 들어가는 자리만
    ...
    if (k == i) { if (l < j + m) continue; }   // 같은 행이면 B는 j+m 이후에서만 시작
```

두 가지가 동시에 맞다 — 시작칸을 `n - m` 까지로 제한해 **잘린 창을 아예 만들지 않았고**,
같은 행일 때 `l >= j + m` 으로 딱 붙는 배치(`l == j + m`)를 살렸다. `l < j` 인 경우는 바깥 루프가
`j` 와 `l` 을 바꿔 다시 도므로 대칭으로 커버된다.

> 같은 문제를 푼 `김준수/week6/벌꿀채취.java` 는 정확히 이 두 곳에서 어긋난다 —
> 겹침을 `j + m >= y` 로 잡아 딱 붙는 배치를 버리고, `n - m` 을 넘는 자리도 시작칸으로 센다.
> 무작위 3,000건 대조에서 96건이 틀렸다. 이 코드는 두 곳 다 맞게 잡았다.

## 개선점

지적할 만한 오류를 찾지 못했다. 아래는 전부 다듬는 수준이다.

### 1. (사소) `board[15][15]` 의 15는 어디서 나온 숫자인가 — <magic-number>

`N ≤ 10` 이므로 `15` 는 여유를 둔 값이고 문제될 게 없다. 다만 `max_board` 도 같은 `15` 라
나중에 제약이 다른 문제에서 이 파일을 복사해 쓸 때 근거가 안 남는다.

```cpp
const int MAXN = 12;   // 문제 제약 N <= 10
int board[MAXN][MAXN];
```

이름 하나만 붙여도 "왜 이 크기인가" 가 코드에 남는다.

### 2. (사소) `find_max` 의 `choose = -1` 은 죽은 값이다 — <dead-code>

`not_choose` 는 재귀 끝에서 `max_value`(항상 0 이상)를 돌려주므로 **`-1` 이 `max` 에서 이길 일이 없다.**
동작에는 문제가 없지만, `-1` 을 보면 "못 고르는 경우를 실패로 표시하나?" 하고 한 번 더 읽게 된다.
`choose = 0` 이거나, `if` 안에서 바로 `max` 를 취하는 편이 뜻이 분명하다.

### 3. (사소) `max_board` 가 케이스 사이에 초기화되지 않는다

`max_board` 는 전역이고 매 케이스 `j <= n - m` 범위만 다시 채워진다. 이전 케이스의 `n` 이 더 컸다면
바깥쪽에 옛 값이 남지만, **읽는 루프도 `j <= n - m` 으로 같은 범위라 실제로는 안 읽힌다.**
지금은 안전하지만, 읽는 범위와 쓰는 범위가 같다는 사실에 기대고 있다는 건 알아두는 게 좋다.

### 4. (사소) `find_max` 는 비트마스크 루프로도 쓸 수 있다

`M ≤ 5` 라 부분집합이 최대 32개다. 재귀 대신 `for (int mask = 0; mask < (1 << m); mask++)` 로
펴면 함수 호출이 사라지고 창 하나당 32번의 단순 루프가 된다. 지금 방식으로도 충분히 빠르므로
**바꿀 필요는 없다** — 취향 차이에 가깝다.

## 복잡도

- 시간: `O(T·(N²·2^M + N⁴))` — 시작칸 `N²` 개마다 부분집합 `2^M`, 그다음 배치 4중 루프.
  `N ≤ 10, M ≤ 5` 라 케이스당 1만 회 수준
- 공간: `O(N²)` — `board` 와 `max_board`

## 요약

부분집합 전탐색으로 "큰 벌통부터 담기" 탐욕의 함정을 피했고, 상태를 인자로만 흘려서 되돌리기 실수의
여지를 없앴다. 무엇보다 **구간 겹침 판정이 정확하다** — 시작칸을 `n - m` 으로 제한하고 같은 행에서
`l >= j + m` 을 쓴 두 곳이 이 문제의 오답이 가장 많이 나오는 지점인데 둘 다 맞다.
고칠 것은 없고, `-1` 같은 죽은 값과 `15` 같은 근거 없는 상수를 정리하는 정도다.
