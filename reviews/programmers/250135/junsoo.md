# [PCCP 기출문제] 3번 / 아날로그 시계 (programmers/250135) — junsoo

## 접근

시침·분침 위치를 계산해 시작 시각의 알람 여부를 먼저 세고, 분 단위로 전진하며 "1분에 초침이 분침·시침을
2번 지나간다"는 가정으로 `alarmCnt += 2` 한 뒤 예외(분침과 정확히 겹치는 순간이라 1번만 울려야 하는
경우)를 보정하는 방식이다. 마지막에 초 단위로 나머지를 처리한다.
코드 상단 주석에 본인이 "3번 다시 풀었는데 다 틀림, 제일 많이 맞춘 B안으로 진행"이라고 적어뒀을
정도로 시행착오가 있었던 문제다.

## 개선점

### 1. (치명) 전체 범위(00:00:00~23:59:59)처럼 여러 시간에 걸친 입력에서 오답 — `logic-edge-case`

공식 예제 7개 중 6개(작은 범위)는 실제로 컴파일해서 맞았지만, 문제 페이지에 실려 있는 마지막 예제
(가장 큰 범위)에서 어긋난다.

```
입력: h1=0,m1=0,s1=0, h2=23,m2=59,s2=59
기대 출력: 2852
실제 출력: 2836   (16개 부족, 실제로 돌려서 확인함)
```

앞의 작은 범위 6개 예제가 전부 통과하는 걸 보면, "분 단위로 2번씩 더하고 시침·분침이 겹치는 순간만
보정"하는 기본 골격 자체는 맞다. 다만 범위가 여러 시간(특히 정시 경계)을 여러 번 지날 때만 어긋나는
걸 보면, 정시(초=분=0)처럼 시침·분침·초침이 동시에 겹치는 경계를 지날 때의 보정(`alarmCnt -= 2` 분기,
`h1%60==0` 일 때의 추가 보정)이 반복 발생하는 경계 전부를 다루지 못하는 것으로 보인다.
**정확히 어느 분기가 원인인지는 코드만 읽어서는 특정하지 못했다 — 이 부분은 확인 못함.**
작은 예제만으로는 이 버그가 드러나지 않으니, 제출 전에 여러 시간(2~3시간 이상)에 걸친 케이스를
직접 만들어 검증해보는 걸 권한다.

## 복잡도

- 시간: `O(경과 초)` — 분·초 단위로 전진. 하루 범위(최대 86400초) 안에서는 충분히 빠르다.
- 공간: `O(1)`

## 요약

기본 골격(분당 2회 + 겹침 보정)은 맞고 작은 범위 예제 6개는 전부 통과한다. 다만 여러 시간에 걸친
큰 범위에서 경계 보정이 어긋나 오답이 난다 — 공식 예제로 실제 재현된 결함이니 제출 전에 반드시 고쳐야 한다.
