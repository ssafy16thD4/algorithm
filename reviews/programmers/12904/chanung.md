# 가장 긴 팰린드롬 (programmers/12904) — chanung

## 접근

길이를 N부터 줄여가며 각 시작 위치에서 팰린드롬인지 검사하고, 처음 찾은 순간 종료하는 방식이다.
"가장 긴 것부터 확인하니 처음 찾은 게 곧 답"이라는 논리가 정확하고, `isPalindrome`도 양끝에서
좁혀가며 첫 불일치에서 바로 멈추는 표준 형태다.

## 개선점

### 1. (사소) 주석의 `O(n^2)`는 이론상 최악 `O(n^3)`이다 — `time-complexity`

`isPalindrome`이 불일치에서 바로 멈추긴 하지만, 이론적 최악의 경우(예: 여러 길이에서 동시에
"거의 팰린드롬"인 대칭 구조가 많은 문자열)에는 길이 O(N) × 시작 위치 O(N) × 검사 O(N)으로
`O(N^3)`이 될 수 있다. N≤2500 기준 `O(N^3)`은 위험한 오더지만, 아래 네 가지 스트레스 패턴으로
N=2500을 직접 돌려본 결과 전부 10ms 이내로 끝났다 — 실제 TLE로 이어지는 입력은 재현하지 못했다
(검증 안 함: 진짜 최악 케이스 존재 여부).

```
교대 패턴(ababab...)      : 0ms
전부 같은 문자(aaaa...)    : 0ms
중앙만 다른 거의-팰린드롬  : 0ms
3주기 패턴(abcabc...)     : 7ms
```

기대 시간복잡도를 확실히 보장하려면 "중심에서 확장"(expand-around-center) 방식으로 바꾸면
이론적으로도 `O(N^2)`가 고정된다.

## 복잡도

- 시간: 실측으로는 `O(N^2)`에 가깝게 동작하지만, 이론상 최악은 `O(N^3)`.
- 공간: `O(1)` — 별도 자료구조 없이 인덱스만 사용.

## 요약

"길이를 줄여가며 첫 번째로 찾은 것이 답"이라는 로직 자체는 옳다. 주석의 복잡도 표기가 이론상
부정확하지만, 여러 스트레스 케이스로 실측했을 때 실제 성능 문제는 관찰되지 않았다.
