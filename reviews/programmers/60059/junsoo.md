# 자물쇠와 열쇠 (programmers/60059) — junsoo

## 접근

자물쇠를 60×60 고정 격자 가운데(오프셋 20)에 배치하고, 열쇠를 4방향 회전×모든 위치로 겹쳐 보면서
자물쇠 영역이 전부 1(정확히 한 번 덮임)이 되는지 검사하는 완전탐색이다. `board[i][j] == 0`(홈이 안
채워짐)과 `== 2`(돌기끼리 겹침)를 같이 걸러내는 `isFull` 판정이 문제 조건과 정확히 맞는다.

주석의 "20-20-20 = 60" 근거를 직접 손으로 다시 계산해봤다. 열쇠 배치 반복문의 좌표 범위
(`20 - key.length` ~ `20 + lock.length`)와 `makeKeyBoard`의 순회 범위(`x` ~ `x + keys 길이`)를
같이 따져보면, `N=M=20`(이 문제의 상한)일 때 최대 인덱스가 정확히 `20+20+20-1 = 59`로 60칸짜리
배열의 끝에 딱 맞고, 최소 인덱스도 정확히 `0`이 된다 — 여유도 없고 모자라지도 않게 배열 크기를
골랐다.

회전 공식(`newKey[j][k] = keys[i-1][k][길이-j-1]`)도 표준 반시계 90도 회전식과 일치하는 걸
직접 대입해서 확인했다(`[[1,2],[3,4]]` → `[[2,4],[1,3]]`). 4번 돌려보면 전부 시도하므로 회전
방향 자체는 어느 쪽이어도 상관없지만, 식이 실제로 유효한 회전을 만들어내는지는 확인해볼 가치가
있었다.

## 개선점

### 1. (사소) 매 시도마다 60×60 전체를 복구한다 — `redundant-loop`

```java
for(int a = 0; a < 60; a++){
    for(int b = 0; b < 60; b++){
        keyBoard[a][b] = board[a][b];
    }
}
```

실제로 `makeKeyBoard`가 건드린 칸은 열쇠 크기만큼(`M × M`)뿐인데, 복구는 매번 60×60(3600칸)
전체를 훑는다. 회전 4가지 × 위치 `(N+M+1)^2`가지를 곱하면 이 문제의 상한(`N,M<=20`)에서도
이 상태 그대로 통과하긴 하지만(직접 계산해보니 대략 2,400만 칸 수준이라 시간 제한 안에서 여유
있다), `makeKeyBoard`가 건드린 좌표만 골라서 `-=`로 되돌리거나 그 범위만 복사하면 낭비가 없다.

```java
private void undoKeyBoard(int[][] board, int keyIndex, int x, int y){
    for(int i = x; i < x + keys[0][0].length; i++){
        for(int j = y; j < y + keys[0][0].length; j++){
            board[i][j] -= keys[keyIndex][i - x][j - y];
        }
    }
}
```

## 복잡도

- 시간: `O(4 · (N+M)^2 · M^2)` — 회전 4가지 × 위치 `O((N+M)^2)` × 위치마다 겹치기/검사에
  `O(M^2)`(복구는 현재 `O(3600)` 고정, 위처럼 바꾸면 `O(M^2)`로 줄어든다). `N,M<=20`인 이 문제
  기준으로 지금 상태로도 충분히 빠르다.
- 공간: `O(1)` — 60×60 고정 크기 배열만 쓴다.

## 요약

경계 계산과 회전 공식을 손으로 다시 확인해봤을 때 정확했고, 판정 조건도 문제 규칙과 맞는다.
매번 전체 60×60을 복구하는 부분만 실제 겹친 범위로 좁히면 더 낭비 없는 코드가 된다.
