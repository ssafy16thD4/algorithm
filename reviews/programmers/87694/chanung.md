# 아이템 줍기 (programmers/87694) — chanung

## 접근

좌표를 2배로 늘린 뒤 **테두리 → 내부** 순서로 두 번 칠하고, 값이 1(테두리)인 칸만 밟는 BFS 로
최단거리를 구해 2로 나눈다. 원래 파일에 적혀 있던 계획의 "지나가는 곳이 어딘지 어떻게 알지"가
정확히 이 문제의 핵심이었고, 답은 **칠하는 순서**다.

## 개선점

### 1. (수정 완료 / 치명) 알고리즘이 없었다 — `wrong-algorithm`

`solution` 이 `System.out.println("모르겠습니다..")` 두 줄이라 `missing return statement` 로
컴파일도 되지 않았다. 접근 자체를 채웠다.

### 2. 왜 좌표를 2배로 늘려야 하는가

정수 격자에서는 직사각형 두 개가 변끼리 딱 붙으면, 두 테두리가 **한 칸에 겹쳐서** 그 사이로
지나갈 수 있는지 없는지 구분이 안 된다. 전부 2배로 늘리면 사이에 칸이 하나 생겨 구분된다.
마지막에 거리를 2로 나누면 원래 좌표계의 답이 된다.

### 3. 왜 "테두리 전부 → 내부 전부" 순서인가

어떤 사각형의 테두리가 다른 사각형 **안쪽**에 들어가면 그 선은 지나갈 수 없다. 테두리를 전부 1로
칠한 다음 내부를 전부 2로 덮어쓰면, 안쪽에 갇힌 테두리가 자동으로 지워진다. 사각형 하나씩
"테두리 칠하고 내부 칠하고"를 반복하면 **이전 사각형의 내부가 나중에 그려진 테두리를 지우지 못해서**
틀린다. 두 루프를 나눈 이유가 이것이다.

```java
for(int[] r : rectangle) { /* 테두리 = 1 */ }
for(int[] r : rectangle) { /* 내부 = 2 (덮어쓰기) */ }
// 이후 board[x][y] == 1 인 칸만 밟는다
```

## 검증

공식 예제 5건 전부 컴파일해서 돌렸다 — `17 / 11 / 9 / 15 / 10`, 기대값과 일치.

## 복잡도

- 시간: `O(K + S^2)` — K = 사각형 칸 칠하기, S = 102(좌표 50×2 + 여유). 사실상 상수다.
- 공간: `O(S^2)` — board, dist.

## 요약

포기 선언만 있던 파일이었다. 이 문제는 아이디어 두 개(2배 확대 / 테두리·내부 2단계 칠하기)를
알면 나머지는 평범한 BFS 다. **정수 격자에서 "붙어 있음"과 "겹침"이 구분되지 않을 때 좌표를 2배로
늘린다**는 기법은 다른 문제에서도 반복해서 나오니 이 문제로 외워두면 좋다.
