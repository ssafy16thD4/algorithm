# [PCCP 기출문제] 3번 / 충돌위험 찾기 (programmers/340211) — chanung

## 접근

로봇마다 경로를 **1초 단위 좌표 목록으로 미리 펼쳐 두고**, 시각 t 마다 살아 있는 로봇들의 좌표를
`Map` 으로 세서 2대 이상인 칸의 개수를 더한다. 위험을 "같은 시각 같은 칸에 2대 이상"으로 정의하니
시뮬레이션 그대로 옮기면 되고, 로봇을 한 마리씩 움직이는 것보다 훨씬 덜 헷갈린다.

## 개선점

### 1. (수정 완료 / 치명) 알고리즘이 없었다 — `wrong-algorithm`

`solution` 이 `return answer;`(0) 한 줄이었다. 접근 자체를 채웠다.

### 2. 이 문제의 함정 — 최단경로가 여러 개다

`(1,1) → (3,4)` 로 가는 최단경로는 여러 갈래인데, 문제는 **행(r)을 먼저 맞추고 그다음 열(c)** 로
가라고 못 박는다. 이 순서를 뒤집으면 지나가는 칸이 달라져서 답이 바뀐다. 코드에서도 while 두 개의
순서가 그 규칙 그대로다.

```java
while(r != to[0]) { r += (to[0] > r) ? 1 : -1; path.add(new int[]{r, c}); }  // 행 먼저
while(c != to[1]) { c += (to[1] > c) ? 1 : -1; path.add(new int[]{r, c}); }  // 그다음 열
```

### 3. 도착한 로봇은 사라진다

경로가 끝난 로봇은 그 칸에 남아 있지 않다. `if(t >= p.size()) continue;` 가 그 처리다.
여기서 "끝나면 제자리에 서 있다"로 잘못 잡으면 없는 충돌이 잡힌다.

### 4. (사소) 좌표를 정수 하나로 눌러 담았다

좌표가 100 이하라 `r*1000 + c` 로 키를 만든다. `int[]` 는 `equals` 가 참조 비교라 `Map` 키로
그냥 쓰면 애초에 동작하지 않는다 — 자주 나오는 함정이다.

## 검증

공식 예제 3건 전부 컴파일해서 돌렸다 — `1 / 9 / 1`, 기대값과 일치.

## 복잡도

- 시간: `O(R × L × D)` — 로봇 수 × 경유지 수 × 구간 이동 거리. 제약(≤100, ≤20, ≤100)에서 여유 있다.
- 공간: 같은 크기의 경로 목록.

## 요약

비어 있던 파일이었다. 이 유형은 "동시에 움직이는 것들"을 **시간축으로 펼쳐 놓고 시각마다 세는**
형태로 바꾸는 순간 쉬워진다. 규칙(행 먼저, 도착하면 사라짐)을 코드로 옮기기 전에 문장으로 확정하는
습관을 들이면 이 문제에서 잃을 점수가 없다.
