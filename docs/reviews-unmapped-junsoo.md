## 1. 최대부분수열 — 대표 풀이

**파일**: `김준수/week6/최대부분수열.java` / **컴파일**: 통과 / **판정**: needs-fix (제약 확인 필요)

주석대로 **"길이 K 인 연속 부분 수열 두 개를 겹치지 않게 골라 합을 최대로"** 로 읽고 리뷰했다.
`안찬웅/week6/14기 3차 1번.java` 와 접근이 같다(`docs/reviews-unmapped-chanung.md` 4번).

### 접근

두 단계다. `memo[i]` 에 시작점 `i` 의 K칸 합을 만들고(`O(N·K)`), `dfs` 로 시작점 두 개 `(i, j)` 조합을
전부 돌며 `j - i ≥ K` 인 것만 `memo[i] + memo[j]` 로 최댓값을 잡는다.
"겹치지 않음 = 두 번째 시작점이 첫 시작점 + K 이상" 을 `memoIdx[1] - memoIdx[0] < K` 로 정확히 옮겼다.

**실제로 돌려본 검증**: 누적합 + 접미사 최댓값 `O(N)` 풀이(아래 수정안, 완전탐색과 이미 대조된 것)와
무작위 900건(`N ≤ 24`, `K ≤ 5`, 값 −50~50)을 대조해 **불일치 0건**. 답은 맞는다.

### 개선점

#### 1. (중요) 쌍 열거가 O(N²) — 파일 주석의 "AI 평가: 아슬아슬함" 은 실측하면 아슬아슬이 아니라 초과다

`dfs` 가 조합 `(i, j)` 를 전부 만들고 리프에서 겹침을 검사한다. 시작점이 `N-K+1` 개라 쌍이 약 N²/2 개다.
**N 제약을 확인하지 못했지만** 실측 결과는 이렇다(K = 1000).

| N | 이 코드 | 안찬웅 이중 루프 | 아래 O(N) 수정안 |
| --- | --- | --- | --- |
| 20,000 | 0.36초 | — | 0.1초 미만 |
| 100,000 | 9.6초 | 2.0초 | 0.1초 |
| 300,000 | 160초 | 34초 | 0.1초 |

같은 O(N²) 인 안찬웅 풀이보다 5배 가까이 느린 건 쌍마다 **재귀 호출 + 배열 쓰기·되돌리기**
(`memoIdx[depth] = i` / `= -1`) 가 들어가서다. 조합 재귀는 "고르는 개수가 가변" 일 때 쓰는 도구고,
딱 2개 고르는 건 이중 `for` 가 맞다. 그리고 이 문제는 그 이중 `for` 도 필요 없다.

핵심은 두 가지. 구간 합은 누적합으로 O(1), "`j ≥ i+K` 중 최대" 는 **뒤에서부터 접미사 최댓값**을
한 번 만들어 두면 `i` 마다 O(1) 이다.

```java
long[] pre = new long[N + 1];
for (int i = 0; i < N; i++) pre[i + 1] = pre[i] + arr[i];

int w = N - K + 1;                        // 시작점 개수
long[] win = new long[w];
for (int i = 0; i < w; i++) win[i] = pre[i + K] - pre[i];

long[] sufMax = new long[w + 1];          // sufMax[i] = max(win[i..w-1])
sufMax[w] = Long.MIN_VALUE / 4;
for (int i = w - 1; i >= 0; i--) sufMax[i] = Math.max(win[i], sufMax[i + 1]);

long best = Long.MIN_VALUE;
for (int i = 0; i + K < w; i++) best = Math.max(best, win[i] + sufMax[i + K]);
```

**검증함** — 위 코드가 원본과 900건 대조에서 불일치 0건이고, 위 표의 시간도 이 코드로 잰 것이다.
`memo` 를 만드는 `O(N·K)` 이중 루프도 누적합으로 대체돼 같이 사라진다.

#### 2. (중요) 합이 `int` 를 넘길 수 있다 — 값 범위 확인 필요

`sum`, `memo[]`, `result` 가 전부 `int` 다. 원소가 10⁹ 급이면 K = 3 만 돼도 넘친다.
누적합 문제는 **합을 담는 변수는 `long`** 으로 두는 게 비용 0 인 습관이다. 위 수정안은 그렇게 했다.

#### 3. (사소) `package algorithm;` + `public class 최대부분수열`

시험 환경이 요구하는 클래스명이 `Solution` 이면 이대로는 컴파일이 안 된다.
같은 폴더의 `게리맨더링.java`, `다리만들기2.java`(BOJ 라 `Main`) 와 같은 지적이다.

#### 4. (사소) `N < 2K` 이면 `Integer.MIN_VALUE` 가 찍힌다

쌍이 하나도 없으면 `result` 초기값이 그대로 출력된다. 문제가 `2K ≤ N` 을 보장하면 무관하다.

### 복잡도

- 시간: `O(N·K + N²)` — 쌍 열거가 지배적. 수정안은 `O(N)`
- 공간: `O(N)`

### 요약

겹치지 않는 조건과 두 단계 구조는 맞고, 무작위 대조에서 전부 정답이다. 문제는 규모다 —
쌍을 전부 도는 대신 **접미사 최댓값 배열 하나**를 두면 O(N) 이고 코드도 더 짧다.
"두 구간 중 하나를 고정하면 나머지는 범위 최댓값 질의" 라는 틀은 이 유형에서 계속 나온다.
