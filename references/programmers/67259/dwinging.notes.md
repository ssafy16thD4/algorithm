### 🚀 프로그래머스 Lv3 [경주로 건설](https://school.programmers.co.kr/learn/courses/30/lessons/67259) (Java)
 
> **날짜:** 2026년 5월 1일 <br>
> **알고리즘:** Dijkstra, 0-1 BFS 응용 <br>
> **언어:** Java 8   <br>
> **핵심 키워드:** PriorityQueue, Deque, Relaxation, Engineering Trade-off

## 📌 문제 개요
$N \times N$ 격자판의 좌측 상단 `(0, 0)`에서 우측 하단 `(N-1, N-1)`까지 경주로를 건설하는 데 필요한 **최소 비용**을 구하는 문제입니다. 인접한 칸으로 이동하는 직선 도로는 100원이 소요되며, 방향을 꺾는 코너를 만들 경우 500원이 추가되어 총 600원이 소요됩니다. 같은 좌표라도 **진입 방향**에 따라 이후 발생하는 비용이 달라지는 것이 특징입니다.

---

## 💡 풀이 핵심 (Core Logic)

### 1. 상태 정의 (State)
*   `visited[y][x][dir]` : `(y, x)` 좌표에 `dir` 방향으로 진입했을 때까지의 최소 누적 비용. 단순 2차원 배열로는 방향 전환에 따른 가중치 변화를 담을 수 없으므로 3차원 배열 상태 관리가 필수적입니다.

### 2. 점진적 최적화 (Step-by-step)
*   **가중치 이산성 활용**: 가중치가 100(직진)과 600(회전) 두 종류뿐이라는 점에 착안, 내부 정렬 비용이 큰 `PriorityQueue` 대신 `Deque`를 도입합니다.
*   **전수 갱신(Relaxation)**: 가중치 격차(100 vs 600)로 인해 덱 내부의 완벽한 정렬이 보장되지 않으므로, 조기 종료(Early Return)를 포기하고 목적지에 도달하더라도 전체 상태가 최적으로 수렴할 때까지 탐색을 지속합니다.

---

## 📊 풀이 방식 비교 (Dijkstra vs 0-1 BFS 응용)

| 비교 항목 | Dijkstra (정격 알고리즘) | 0-1 BFS 응용 (구조적 최적화) |
| :--- | :--- | :--- |
| **핵심 자료구조** | `PriorityQueue<Node>` | `ArrayDeque<Node>` (Deque) |
| **정렬 오버헤드** | 삽입/삭제 시 $O(\log N)$ 발생 | **$O(1)$** (앞/뒤 삽입 연산만 수행) |
| **탐색 종료 시점** | 목적지 `poll()` 즉시 조기 종료 | 목적지 도달 후에도 갱신 완료까지 지속 |
| **테케 성능 차이** | 안정적이나 무거움 (테케 10: **10.31ms**) | 특정 케이스 압도적 효율 (테케 10: **1.63ms**) |

---

## 🛠 성능 최적화 인사이트 (Performance Insights)

### 1. 상수 시간($c$) 최적화와 자료구조
*   Java 환경에서 `PriorityQueue`의 힙 재구조화 연산은 비용이 큽니다. 직진은 `addFirst()`, 회전은 `addLast()`로 삽입하는 덱 구조를 활용하여 정렬 과정 자체를 생략함으로써 최대 **10배의 실행 속도 향상**을 이뤄냈습니다.

### 2. 메모리 및 객체 연산 오버헤드 (Low-level)
*   `PriorityQueue`는 필연적으로 내부 요소 비교를 위해 `Comparable` 인터페이스 호출 및 객체 간 비교 연산을 수행합니다. 덱을 사용할 경우 이러한 JVM 단의 비교 연산 사이클을 완전히 걷어낼 수 있어 캐시 효율성이 극대화됩니다.

### 3. 엔지니어링 트레이드오프 (Trade-off)
*   완벽한 정렬을 유지하는 비용(Dijkstra)과 약간의 중복 탐색을 허용하며 갱신하는 비용(Modified 0-1 BFS)을 저울질했을 때, 가중치 종류가 제한적인 도메인에서는 후자가 실전 퍼포먼스 면에서 훨씬 강력함을 증명했습니다.

## 🧠 회고 및 결론

1.  **고정관념의 탈피**: "가중치가 있는 최단 거리는 반드시 다익스트라"라는 공식에서 벗어나, 데이터의 특성(100과 600, 두 종류의 가중치)을 활용해 0-1BFS 응용 방식도 가능하다는 것을 확인함
2.  **가설과 검증**: 조기 종료가 오답을 발생시키는 원인을 파악하고, 이를 SPFA(Shortest Path Faster Algorithm) 형태의 전수 갱신 로직으로 변형하여 정확성과 속도를 동시에 챙김
3.  **데이터 중심의 사고**: 알고리즘은 도구일 뿐, 핵심은 처리해야 할 '데이터의 형태'에 맞춰 유연하게 설계를 비틀 수 있는 엔지니어링적 사고방식임을 체감할 수 있었음
