### 프로그래머스 Lv3 [양과 늑대](https://school.programmers.co.kr/learn/courses/30/lessons/92343) (Java)

> **날짜:** 2026년 7월 18일 <br>
> **알고리즘:** DFS, 비트마스킹<br>
> **언어:**  Java <br>
> **핵심 키워드:** DFS, 비트마스킹

## 📌 문제 개요

* **설명:** `0`번 노드를 루트로 하는 이진 트리가 주어진다. 각 노드에는 양 또는 늑대가 한 마리씩 존재하며, 루트 노드에서 시작해 노드를 방문할 때마다 해당 노드의 양 또는 늑대가 따라오게 된다. 이때 어느 시점에서든 늑대의 수가 양의 수 이상이 되면 양이 모두 잡아먹히므로, 항상 `양의 수 > 늑대의 수` 조건을 유지해야 한다. 조건을 만족하면서 방문할 수 있는 노드들을 선택했을 때, 모을 수 있는 양의 최대 수를 반환해야 한다.
* **제약 조건:**

  * $2 \le info.length \le 17$
  * `info[i]`는 `i`번 노드의 정보를 나타낸다.
  * `info[i] == 0`이면 양, `info[i] == 1`이면 늑대를 의미한다.
  * `info[0] == 0`이며, `0`번 노드는 항상 루트 노드이다.
  * `edges.length == info.length - 1`
  * `edges[i]`는 `[부모 노드 번호, 자식 노드 번호] 형태로 주어진다.
  * 입력은 항상 하나의 유효한 이진 트리 형태로 주어진다.

## 💡 풀이 핵심 (Core Logic)

### 1. 현재 노드 기준 DFS가 아닌 후보 집합 기반 탐색

* 이 문제는 단순히 현재 노드에서 자식 노드로 내려가는 일반적인 트리 DFS로 해결하기 어렵다.
* 특정 노드를 방문하면 그 노드의 자식들이 새롭게 방문 가능한 후보가 되며, 이후에는 현재 위치와 관계없이 지금까지 열린 후보 노드들 중 하나를 선택할 수 있다.
* 따라서 탐색 상태는 현재 노드 하나가 아니라, **현재 방문 가능한 후보 노드 집합**을 기준으로 관리해야 한다.

### 2. 후보 노드 중 하나를 선택하며 모든 방문 순서 탐색

* 현재 후보 집합에서 노드 하나를 선택한다.
* 선택한 노드가 양이면 양의 수를 증가시키고, 늑대면 늑대의 수를 증가시킨다.
* 선택 후 `늑대의 수 >= 양의 수`가 되면 해당 선택은 불가능하므로 탐색하지 않는다.
* 조건을 만족하는 경우에는 선택한 노드를 후보 집합에서 제거하고, 해당 노드의 자식들을 새로운 후보 집합에 추가한다.
* 이 과정을 반복하면서 가능한 모든 방문 순서를 탐색한다.

### 3. 각 분기별 양과 늑대 수를 상태로 관리

* 양의 수와 늑대의 수는 전역으로 관리하지 않고, 각 DFS 분기에서 누적 상태로 전달한다.
* 서로 다른 방문 순서는 서로 다른 양/늑대 수와 후보 집합을 가지므로, 각 분기는 독립적으로 처리되어야 한다.
* 전역 변수로는 현재까지 모은 양의 최대 수만 관리한다.

### 4. 비트마스킹으로 후보 집합 표현

* `info.length`의 최대값이 17이므로, 방문 가능한 후보 노드 집합을 하나의 정수 비트로 표현할 수 있다.
* `bit`의 `i`번째 비트가 켜져 있으면 `i`번 노드가 현재 선택 가능한 후보라는 의미이다.
* 후보 노드 선택, 제거, 자식 추가는 비트 연산으로 처리할 수 있다.

```java
// i번 노드가 후보인지 확인
(bit & (1 << i)) != 0

// i번 노드를 후보에서 제거
bit & ~(1 << i)

// child 노드를 후보에 추가
bit | (1 << child)
```

## 🛠 성능 최적화 인사이트 (Performance Insights)

### 1. 배열 또는 리스트 복사 방식

* 후보 집합을 `List<Integer>`로 관리하는 방식도 가능하다.
* 이 경우 DFS의 각 분기마다 후보 목록을 복사한 뒤, 선택한 노드를 제거하고 자식 노드를 추가한다.
* 후보 목록을 복사하는 이유는 한 분기의 선택이 다른 형제 분기의 후보 목록에 영향을 주면 안 되기 때문이다.

```java
List<Integer> nextCandidates = new ArrayList<>(candidates);
nextCandidates.remove(i);
nextCandidates.addAll(children);
```

* 이 방식은 구현 의도가 직관적이지만, 분기마다 리스트 객체가 생성되고 원소 복사가 발생한다.

### 2. 비트마스킹을 활용한 후보 집합 관리

* 노드 수가 최대 17개로 작기 때문에 후보 집합을 정수 하나로 관리할 수 있다.
* 비트마스킹을 사용하면 리스트 복사 없이 정수 연산만으로 후보 추가와 제거가 가능하다.
* 각 DFS 분기에서 `nextBit` 값을 새로 계산해 전달하므로, 후보 집합의 독립성도 유지된다.

```java
int nextBit = bit & ~(1 << i);

for (int child : tree[i]) {
    if (child == 0) break;
    nextBit |= (1 << child);
}
```

### 3. 비트마스킹의 이점

* 후보 집합 복사 비용을 줄일 수 있다.
* 후보 포함 여부를 빠르게 확인할 수 있다.
* 후보 제거와 추가를 간단한 비트 연산으로 처리할 수 있다.
* 노드 수가 작은 완전탐색 문제에서 상태 표현이 간결해진다.

### 4. 문제 조건을 활용한 배열 초기화 최적화

* 입력은 항상 `0`번 노드를 루트로 하는 트리이다.
* 루트 노드는 어떤 노드의 자식으로 등장하지 않으므로, 자식 노드 번호로 `0`이 등장하지 않는다.
* 이 조건을 활용하면 `tree` 배열의 기본값 `0`을 빈 자식 값으로 사용할 수 있다.
* 따라서 별도의 `-1` 초기화를 생략할 수 있다.

```java
tree = new int[n][2];

if (tree[parent][0] == 0) {
    tree[parent][0] = child;
} else {
    tree[parent][1] = child;
}
```

* 이는 문제 조건을 분석해 기본값을 sentinel로 활용한 방식이며, 초기화 비용을 줄이는 효과가 있다.

## 🛠 트러블 슈팅

### 1. 비트 포함 여부 비교 실수

* 비트마스킹에서 특정 비트가 켜져 있는지 확인할 때, 결과값을 `1`과 비교하면 안 된다.
* `bit & (1 << i)`의 결과는 `i`번째 비트 값이므로, `i == 0`일 때만 `1`이 된다.
* 예를 들어 `i == 3`이면 결과값은 `8`이므로, `== 1` 비교는 실패한다.

```java
// 잘못된 방식
if ((bit & (1 << i)) == 1) {
    ...
}
```

* 따라서 특정 비트가 켜져 있는지는 `0`보다 큰지 또는 `0`이 아닌지로 확인해야 한다.

```java
// 올바른 방식
if ((bit & (1 << i)) != 0) {
    ...
}
```

또는

```java
if ((bit & (1 << i)) > 0) {
    ...
}
```

### 2. 양과 늑대 수 계산 실수

* `info[i] == 0`이면 양, `info[i] == 1`이면 늑대이다.
* 따라서 양의 수는 `info[i] ^ 1`로 증가시킬 수 있고, 늑대의 수는 `info[i]`를 그대로 더하면 된다.

```java
int ns = sheep + (info[i] ^ 1);
int nw = wolf + info[i];
```

* 양과 늑대 모두에 `info[i] ^ 1`을 더하면, 양 노드에서 양과 늑대가 동시에 증가하는 잘못된 계산이 된다.

```java
// 잘못된 방식
int ns = sheep + (info[i] ^ 1);
int nw = wolf + (info[i] ^ 1);
```

### 3. 후보 집합과 방문 처리의 혼동

* 이 문제에서는 별도의 `visited` 배열을 두지 않아도 된다.
* 선택한 노드를 후보 집합에서 제거하는 것이 해당 노드를 방문 처리하는 역할을 한다.
* 이후 해당 노드의 자식만 후보에 추가하므로, 이미 선택한 노드를 다시 선택해 양이나 늑대를 중복 카운트하지 않는다.

```java
int nextBit = bit & ~(1 << i);
```

* 즉, 이 문제의 핵심 상태는 현재 위치가 아니라 `현재 선택 가능한 후보 집합`이다.
* 후보 집합에서 제거된 노드는 이미 방문한 노드로 간주할 수 있다.


## 🧠 회고 및 결론

개인적으로 까다로운 문제였다. 양을 데리고, 다른 분기를 어떻게 방문할 것인가에 대한 고민이 많았고, 늑대를 지나갈 수 있는 케이스를 구분하는 것이 어려웠다. 

처음에는 일반 큐와 늑대 큐를 활용해 늑대를 후보군으로 두고, BFS 방식을 시도하였다. 그러나 노드 방문 과정에서 늑대 수를 어떻게 관리할 것인가에 대한 모순이 발생하였고 BFS 방식은 불가능하다는 것을 알게 되었다.

DFS를 사용했을때 후보군을 관리하면, 다양한 경우의 수를 처리할 수 있다는 것을 배웠다.
