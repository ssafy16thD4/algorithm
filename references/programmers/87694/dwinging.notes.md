## 📌 문제 개요

* **설명:** 여러 개의 직사각형이 겹쳐 만들어진 다각형 지형에서, 캐릭터가 바깥쪽 테두리를 따라 아이템까지 이동하는 최단거리를 구하는 문제이다.

* 각 직사각형의 변은 x축과 y축에 평행하며, 여러 직사각형은 하나의 연결된 지형을 구성한다.

* 캐릭터는 직사각형 내부를 통과할 수 없으며, 직사각형들이 합쳐진 전체 도형의 가장 바깥쪽 테두리만 따라 이동할 수 있다.

* 캐릭터와 아이템은 모두 다각형의 테두리 위에 위치한다.

* 서로 다른 직사각형이 꼭짓점에서 만나거나 변이 겹치는 경우는 주어지지 않는다.

* 지형이 둘 이상으로 분리되는 경우와 하나의 직사각형이 다른 직사각형 안에 완전히 포함되는 경우도 주어지지 않는다.

* 원래 좌표를 그대로 격자에 표시하면, 실제로는 연결되지 않은 경로가 꼭짓점 부근에서 연결된 것처럼 표현될 수 있다.

* 이를 방지하기 위해 모든 좌표를 2배로 확장한 뒤 지형을 구성한다.

```java
int lx = rec[0] << 1;
int ly = rec[1] << 1;
int rx = rec[2] << 1;
int ry = rec[3] << 1;
```

* 좌표를 2배로 확장했으므로, 최종 이동거리는 다시 2로 나누어 반환한다.

* **제약 조건:**

  * 직사각형의 개수는 `1`개 이상 `4`개 이하이다.
  * 모든 좌표값은 `1` 이상 `50` 이하이다.
  * 캐릭터와 아이템은 전체 도형의 테두리 위에 위치한다.
  * 캐릭터와 아이템의 초기 위치는 서로 다르다.

## 💡 풀이 핵심 (Core Logic)

### 1. 모든 좌표를 2배로 확장

* 원래 좌표를 그대로 사용하면 서로 다른 테두리가 가까이 위치한 지점에서 실제로는 이동할 수 없는 경로가 연결된 것처럼 처리될 수 있다.

* 직사각형과 캐릭터, 아이템의 모든 좌표를 2배로 확장하여 테두리 사이의 간격을 명확하게 구분한다.

```java
int characterX = originalCharacterX << 1;
int characterY = originalCharacterY << 1;
int itemX = originalItemX << 1;
int itemY = originalItemY << 1;
```

### 2. 직사각형 영역을 채워 하나의 도형으로 구성

* 각 직사각형의 경계와 내부를 모두 격자에 표시한다.

* 여러 직사각형이 겹치는 영역도 동일한 값으로 채워지므로, 최종적으로 모든 직사각형의 합집합이 하나의 도형으로 표현된다.

```java
for (int y = ly; y <= ry; y++) {
    for (int x = lx; x <= rx; x++) {
        map[y][x] = AREA;
    }
}
```

### 3. 첫 번째 BFS로 테두리와 내부를 분류

* 캐릭터의 시작점에서 채워진 영역을 BFS로 탐색한다.

* 새로운 좌표를 방문할 때마다 주변 8방향을 확인한다.

* 주변 8방향 중 하나라도 빈 공간이 존재하면 테두리로 분류한다.

* 모든 방향이 채워져 있다면 도형 내부로 분류한다.

```java
private int checkOutLine(int[][] map, int y, int x) {
    for (int[] d : EIGHT_DIR) {
        int ny = y + d[0];
        int nx = x + d[1];

        if (!check(ny, nx) || map[ny][nx] == EMPTY) {
            return OUTLINE;
        }
    }

    return INSIDE;
}
```

* 첫 번째 BFS는 채워진 영역을 순회하는 동시에 각 좌표를 테두리와 내부로 구분한다.

```text
0: 빈 공간
1: 아직 분류되지 않은 영역
2: 내부 또는 방문 처리된 좌표
3: 이동 가능한 테두리
```

### 4. 두 번째 BFS로 최단거리 계산

* 캐릭터의 시작점에서 다시 BFS를 수행한다.

* 이번에는 테두리로 분류된 좌표만 상하좌우로 이동한다.

```java
if (map[ny][nx] == OUTLINE) {
    map[ny][nx] = VISITED;

    queue[tail][0] = ny;
    queue[tail][1] = nx;
    queue[tail][2] = move + 1;
    tail++;
}
```

* BFS는 각 좌표까지의 최단거리를 보장하므로, 아이템 좌표에 처음 도달했을 때의 이동 횟수가 정답이 된다.

* 좌표를 2배로 확장했으므로 최종 이동거리는 2로 나누어 반환한다.

```java
return move >> 1;
```

```text
좌표 2배 확장
→ 직사각형 합집합 생성
→ 첫 번째 BFS로 테두리와 내부 분류
→ 두 번째 BFS로 아이템까지의 최단거리 계산
```

## 📊 풀이 방식 비교

### BFS로 테두리 분류 후 탐색 vs BFS 중 실시간 테두리 판별

### 1. BFS로 테두리 분류 후 탐색

* 직사각형의 전체 영역을 채운 뒤, 첫 번째 BFS를 수행한다.

* 첫 번째 BFS에서는 채워진 영역 전체를 순회하며 각 좌표가 테두리인지 내부인지를 분류한다.

* 분류가 끝나면 두 번째 BFS를 수행하여 테두리만 따라 아이템까지의 최단거리를 구한다.

```text
직사각형 합집합 생성
→ BFS로 테두리와 내부 분류
→ 테두리 최단거리 BFS
```

#### 장점

* 테두리 판별과 최단거리 탐색이 서로 분리되어 있다.

* 테두리 판별은 각 영역 좌표를 방문할 때 한 번만 수행한다.

* 두 번째 BFS에서는 좌표값만 확인하면 되므로 탐색 조건이 단순하다.

```java
if (map[ny][nx] == OUTLINE) {
    // 이동
}
```

#### 단점

* 영역 분류와 최단거리 탐색을 위해 BFS를 두 번 수행한다.

* 첫 번째 BFS에서 각 좌표의 주변 8방향을 추가로 확인해야 한다.

---

### 2. BFS 중 실시간 테두리 판별

* 직사각형의 합집합만 생성하고, 테두리와 내부를 사전에 분류하지 않는다.

* 캐릭터의 시작점에서 최단거리 BFS를 수행하면서 상하좌우의 이동 후보를 확인한다.

* 각 이동 후보가 실제 테두리에 해당하는지 주변 좌표를 통해 실시간으로 판별한다.

```java
if (map[ny][nx] == AREA && isOutline(map, ny, nx)) {
    visited[ny][nx] = true;
    queue.add(new int[]{ny, nx, move + 1});
}
```

```text
직사각형 합집합 생성
→ 최단거리 BFS
→ 이동 후보마다 테두리 여부 판별
```

#### 장점

* 별도의 테두리 분류 과정이 필요하지 않다.

* BFS를 한 번만 수행한다.

* 실제 이동 경로에 포함되는 후보만 대상으로 테두리 여부를 확인할 수 있다.

#### 단점

* 이동 후보를 확인할 때마다 주변 좌표를 추가로 검사해야 한다.

* 하나의 좌표가 여러 인접 좌표의 이동 후보로 등장하면, 방문 처리 시점에 따라 테두리 판별 연산이 반복될 수 있다.

* 최단거리 탐색 과정에 외곽선 판별 조건이 포함되어 실행 흐름이 복잡해진다.

---

### 3. 두 방식 비교

| 항목          | BFS로 분류 후 탐색   | BFS 중 실시간 판별        |
| ----------- | -------------- | ------------------- |
| 도형 구성       | 직사각형 전체 영역을 채움 | 직사각형 전체 영역을 채움      |
| BFS 횟수      | 2회             | 1회                  |
| 테두리 판별 시점   | 첫 번째 BFS       | 최단거리 BFS의 이동 과정     |
| 테두리 판별 대상   | 채워진 영역 전체      | 실제 이동 후보            |
| 최단거리 BFS 조건 | 테두리 값만 확인      | 테두리 여부를 추가로 계산      |
| 실행 구조       | 단계가 분리되어 단순함   | 단계는 적지만 조건이 복잡함     |
| 중복 판별 가능성   | 좌표마다 한 번       | 이동 후보 확인 과정에서 발생 가능 |

* BFS 횟수만 보면 실시간 판별 방식이 유리해 보일 수 있다.

* 그러나 실제 연산에서는 BFS 횟수 외에도 조건문 수, 주변 좌표 접근 횟수, 분기 구조가 성능에 영향을 준다.

## 🛠 성능 최적화 인사이트 (Performance Insights)

### 1. 시간복잡도만으로는 실제 성능 차이를 설명하기 어렵다

* 좌표를 2배로 확장하더라도 격자 크기는 약 `100 × 100` 수준이다.

* 전체 격자 크기를 `G`, 테두리 판별을 위해 확인하는 방향 수를 `D`라고 한다.

```text
BFS로 테두리 분류 후 탐색
O(G × D) + O(G)

BFS 중 실시간 테두리 판별
O(G × D)
```

* `D`는 최대 8인 상수이므로, 두 방식 모두 점근적으로는 `O(G)`로 표현할 수 있다.

* 따라서 빅오 표기만으로는 두 방식의 실제 실행 성능 차이가 명확하게 드러나지 않는다.

### 2. BFS로 분류한 뒤 탐색하는 방식

* 첫 번째 BFS에서는 영역 좌표를 방문하며 테두리 여부를 한 번씩 판별한다.

* 두 번째 BFS에서는 이미 분류된 좌표값만 확인한다.

```java
if (map[ny][nx] == OUTLINE) {
    // 이동
}
```

* 탐색 단계별 역할이 분리되어 있으며, 두 번째 BFS의 조건문은 비교적 단순하고 일정하다.

* BFS를 두 번 수행하지만, 최단거리 탐색 과정에서는 복잡한 판별 연산이 발생하지 않는다.

### 3. BFS 중 실시간으로 판별하는 방식

* BFS 횟수는 한 번이지만, 이동 후보를 확인할 때마다 주변 방향을 추가로 검사한다.

```java
for (int[] d : EIGHT_DIR) {
    int sy = ny + d[0];
    int sx = nx + d[1];

    if (map[sy][sx] == EMPTY) {
        return true;
    }
}
```

* 테두리 좌표는 빈 공간을 발견한 시점에 반복문이 종료될 수 있다.

* 내부 좌표는 모든 방향을 확인한 뒤에야 테두리가 아니라는 결론을 내릴 수 있다.

* 도형의 형태와 좌표의 위치에 따라 반복문 종료 시점과 조건문의 결과가 달라진다.

### 4. CPU 분기 예측

* CPU는 조건문의 결과를 미리 예측하여 다음 명령을 준비한다.

* 동일한 결과가 반복되는 단순한 조건문은 비교적 예측하기 쉽다.

* 반대로 조건 결과와 반복문 종료 위치가 불규칙하면 분기 예측 실패가 발생할 가능성이 높아진다.

```text
외곽선 좌표
→ 1~8번째 검사 중 빈 공간을 발견하면 종료

내부 좌표
→ 8방향을 모두 검사한 뒤 종료
```

* 실시간 판별 방식은 좌표마다 검사 횟수와 종료 지점이 달라진다.

* 이 과정에서 발생하는 불규칙한 조건 분기는 CPU의 분기 예측에 불리하게 작용할 수 있다.

* 분기 예측에 실패하면 CPU는 미리 처리하던 명령을 폐기하고 올바른 분기부터 다시 실행해야 한다.

### 5. 메모리 접근 구조

* 두 방식 모두 주변 좌표를 확인하므로 기본적인 배열 접근 형태는 유사하다.

* 다만 분류 후 탐색 방식은 최단거리 BFS에서 이미 계산된 테두리 값을 재사용한다.

* 실시간 판별 방식은 이동 후보마다 주변 좌표를 다시 확인해야 한다.

```text
분류 후 탐색
→ 테두리 판별 결과를 맵에 저장
→ 이후 단순 조회

실시간 판별
→ 이동 과정에서 주변 상태를 반복 확인
```

* 이는 계산 결과를 미리 저장하여 재사용하는 방식과, 필요할 때마다 다시 계산하는 방식의 차이로 볼 수 있다.

### 6. 실제 성능 관점의 결론

* 실시간 판별 방식은 BFS를 한 번만 수행하므로 이론적으로는 연산량이 적어 보일 수 있다.

* 반면 분류 후 탐색 방식은 BFS를 두 번 수행하지만, 테두리 판별 결과를 저장하고 최단거리 탐색에서는 단순한 조건만 반복한다.

* 따라서 실제 CPU 실행에서는 다음 요소가 성능을 결정한다.

```text
BFS 수행 횟수
테두리 판별 횟수
조건문 실행 횟수
분기 예측 성공률
주변 배열 접근 횟수
판별 결과의 재사용 여부
```

* 이 문제의 격자 크기는 작기 때문에 두 방식 모두 제한 시간 내에서 충분히 동작한다.

* 이 비교의 핵심은 어느 방식이 시간 초과를 피하는지가 아니다.

* 동일한 시간복잡도를 가진 알고리즘도 조건 분기와 메모리 접근, 계산 결과의 재사용 여부에 따라 실제 성능이 달라질 수 있다는 점을 확인하는 데 의미가 있다.
